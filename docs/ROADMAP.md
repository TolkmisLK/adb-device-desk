# Roadmap / 开发路线

## v0.1 — 单设备连接与诊断

目标用户：需要用 Windows 连接和调试安卓设备的开发者与测试人员。

核心流程：配置 ADB → 发现/配对设备 → 明确选择设备 → 诊断或操作 → 导出结果。

### Acceptance criteria

- 不安装 ADB 时，界面可启动并提供可执行的配置步骤。
- 展示 USB、TCP 和 ADB 已发现的 mDNS 设备；不把未经授权或离线设备当作可操作设备。
- 配对与连接使用独立端口；六位配对码只通过 stdin 传入，不保存，不记录到报告。
- ADB 操作使用参数数组，不经过 shell；所有设备操作都显式使用 `-s`。
- 截图按原始字节保存；文本错误不能当作 PNG 保存。
- 诊断报告不包含目标地址、序列号、文件路径、配对码或原始命令输出。
- 超时终止本次客户端，输出量有上限，界面保持响应；不自动停止共享 ADB 服务。
- 宽屏与较窄窗口的中英界面可用；ADB 可执行文件和报告导出路径由用户选择。
- 静态分析、单元/进程/界面测试、Windows Release 构建通过。
- Windows 真机 USB、无线配对、连接、安装、截图、日志验收通过后，发布 v0.1.0。

## v0.2 — 根据真实使用反馈完善

候选项：设备备注、最近连接（明确选择是否记忆地址）、更细的错误解释、mDNS 连接与断开体验。先收集问题，再确定范围。

## Later

同一 APK 的多设备批量安装已纳入首版；投屏整合、其他批量操作和 macOS 支持单独评估。首版不为这些候选需求引入额外框架。

## Engineering decisions

- Flutter 桌面与 Dart；调用官方 ADB，不重新实现协议。
- 仅使用一个运行时插件 `file_selector` 提供系统文件选择框。
- 配置仅存储 ADB 路径与语言；无账户、数据库或后端服务。
- 先交付可用的小版本。版本号代表实际能力和兼容性，不预设大量空版本。
